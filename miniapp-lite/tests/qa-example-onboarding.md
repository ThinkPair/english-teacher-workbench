## 原因与此前验收缺口

`_loadSpace` 只有在不存在当前 archive 和旧 personal 存储键时才生成默认示例。只要已有键，即使内容是合法空库，也读取保留该库：

| 合成启动条件 | 修复前既有行为 |
|---|---|
| 所有档案键缺失 | 自动建立 10 份示例、40 条成绩 |
| 旧 personal 合法空库 | 保持 0 份，不写新键 |
| 已有 v3 archive 空库 | 保持 0 份，原字节不变 |
| 已有 v4 archive 空库 | 保持 0 份 |
| 已有自行填写的档案 | 原样保留，不静默追加示例 |
| 删除示例后重启 | 保持删除结果，不重新生成 |

因此“没有看到示例”可以由已有空存储键复现，不能仅凭用户界面判断是初始化失败。此前全新无键的官方验收不足以证明返回用户能发现示例。修复采用明确追加入口，继续保留防覆盖和防自动复活的规则。

## 目标回归覆盖

- **追加完整且不改输入。** 一次新增 10 份示例、40 条成绩、8 个标签和 1 条计划；整库校验后返回独立数据，修订号只增加 1。
- **真实记录与编号保护。** 即使已有非示例档案使用旧 demo 编号或含示例字样，既有内容仍逐项保留。新学员、成绩、标签、计划重新生成编号，关联只指向对应新学员，没有覆盖或串档。
- **分类复用遵从现有设置。** 同名分类按规范化名称复用，保留其既有满分；缺少的分类才追加。新示例分数按对应比例适配目标满分，保留两位并不超过满分，含 0.03 这一小数边界；旧分类、旧学员和旧成绩不变。
- **重复与容量保护。** 只要仍存在任一示例就拒绝再加一批；重复点击和重入不会生成第二批。学生数、分类数、修订号或数据格式不合法时原子失败。原库未超过 900 KiB、但追加后超过的情况也保留原盘和全部既有记录。
- **旧空库实际路径。** 旧 personal 空库点击后写当前键但保留旧字节；旧 v3 archive 空库点击后保存格式 4，重启仍是同一批示例。
- **可见性与失败恢复。** 成功后清空搜索／待跟进筛选，并选中首个新增示例所属分类，立即可见 4 张示例卡。写入失败保留原库、原筛选与分组，可重试；外部盘发生变化时不覆盖。
- **操作边界。** 表单、脏草稿或坏库状态下伪造添加动作均不改变内容。删除全部示例后重启不自动复活；再次主动添加时使用新编号，并复用已有分类。
