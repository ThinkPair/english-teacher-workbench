验收日期：2026-10-04。测试只使用 pytest 临时目录、虚构学生和本机 HTTP 模拟模型服务；没有读取或发送真实学生资料，没有验证任何真实模型的识图或教学效果。

## 覆盖范围

1. 真实工作区初始为空；示例数据不会进入真实工作区。
2. 学生、试卷、文件、任务和教案数据按工作区隔离；教师模型配置按最新合同有意全局共用。
3. 学生历史及发给模型的教案依据不混入其他学生或未经确认的试卷。
4. 学校原分、题目学校分、AI 建议分分别保存；确认后统计使用老师确认得分。
5. 空题目、未校对题目、缺少老师确认得分均不能确认，包括练习卷。
6. 过期 revision 返回 409，不覆盖新版；不合法分数不发生部分写入。
7. 修改已确认试卷或新增附件后重新进入复核，既有依据教案标记过期。
8. 处理中老师改卷时，晚到的识别结果被拒绝。
9. 错误 JSON、模型 HTTP 错误、缺少教案正文不会产生假成功或假数据。
10. 未配置模型不能假装识别；仅上传原图不会发起模型请求。
11. 重新识别保留老师已有单题学校分、满分和批注，并要求重新校对。
12. 题目不能引用另一名学生的原图。
13. 9 页 PDF 明确超过单次 8 页上限，拒绝前未发送任何页面，不静默截取部分。
14. 密钥不会出现在设置、初始化、任务及错误响应；空密钥保留已有值，显式清除有效。
15. 工作区备份包含一致的 SQLite 快照与原图，不包含另一工作区数据、设置或密钥。
16. 真正关闭并重启后端进程后，学生、确认试卷、原图、教案和课后记录保留。
17. 模型处理过程中强制关闭进程，重启后原任务变为失败，未写入半成品题目。

## 复验命令

在工程目录执行：

```powershell
./.venv/Scripts/python.exe -m pytest tests -q --tb=short
```

`test_api_acceptance.py` 使用 TestClient 和明确的 localhost 模型 stub；`test_process_persistence.py` 启动独立本机后端进程并重启。所有状态写入 pytest 临时目录，模型 stub 的密钥是源码内明确标注的虚构测试字符串。

## v0.2 教材、真题库与针对性练习验收（2026-10-04）

依据冻结的 `V02_CONTRACT.md`，新增 `test_v02_acceptance.py` 与 `test_v02_persistence.py`，首批 27 个展开用例与旧版 25 个用例合并运行：52 passed，34.62 秒。随后针对复测卷来源映射增补 1 个完整链路用例，目前新用例共 28 个，最终完整回归为 **53 passed，38.72 秒**；保留 1 条 Starlette TestClient/httpx 弃用警告。

所有材料、学校、学生、题目和模型响应均为明确虚构测试样本；模型接口只连接本机 HTTP stub。没有使用真实 API 密钥，没有验证真实模型的 OCR、拆题准确率或教学效果。

已验证：

1. 资料、题库题、原件/预览 URL、练习及转卷按 workspace 隔离；同一空间资料供不同学生复用，但各学生练习和选题依据独立。
2. 60 页 PDF 导入不产生任何页面栅格化调用；请求第 59 页时只渲染该页；原始 PDF 字节完整保留，文字页本机搜索定位正确。
3. 多份 PDF 与照片同属一份资料时，全局页码按文件顺序延续；照片明确没有本机提取文本。
4. 坏 PDF、伪装文件、加密 PDF、501 页 PDF 被拒绝；无部分文档与原件遗留。首轮发现坏 PDF 解析在 Windows 留句柄导致清理失败，改用有界字节流解析后已通过完整复验。
5. 题库题默认草稿；缺少答案/知识点不能确认，错误页码范围被拒绝；PUT 不能改变所属资料，旧 revision 被拒绝，修改已确认题后回到草稿。
6. 自动推荐仅取当前学生已确认学校卷的老师确认失分；其他学生、未确认卷、复测卷、只有 AI 扣分但老师满分/未评分的题不产生自动目标。
7. 归一化知识点别名可匹配；默认仅同年级真题，教材和其他年级须显式扩展。题库不足返回实际差额，无目标/无匹配时不填入无关题、不请求模型编题。
8. 阅读共享材料、选项、答案及页码保留；保存练习后修改题库不会改写旧练习快照，来源页仍可打开。
9. 转为复测卷时清空学生答案、老师分、AI 分与确认状态，保留题干/阅读/选项；重复转卷返回同一试卷，不修改学校原卷。
10. 生成或保存练习不算完成；复测修改后确认才排除已练题，重新打开复核后不再视为完成；学校最近成绩不被复测成绩取代。
11. 拆题仅发送选定页；无效页集合在模型请求前拒绝，异常 JSON、空题、越界题源、模型 HTTP 错误均不能写入假题；错误响应不回显密钥。
12. 重复与并发拆题不会重复入库，也不会覆盖老师已修改的题；文档 revision 更新后拒绝迟到结果。
13. 明确构造只有旧版 6 张表的 v0.1 数据库，实际启动 v0.2 后学生、已确认成绩、原图、教案和课后笔记保留；第一次备份数据库完整可读。已有旧 demo seed 仍能增量生成一次新虚构资料，个人资料库不被播种。
14. 实际关闭、重启进程后，原件、题库、练习快照与已关联复测试卷保留且转卷仍幂等；拆题中强制关闭，重启后任务失败且不落部分题库数据。
15. 备份包含一致的数据库、旧试卷原件及资料库原件，排除预览缓存、配置和密钥。

旧用例仅有一处按新合同调整：练习确认后的 `latest_score` 应保持空，而非把练习成绩视为学校成绩；该用例仍独立检查老师确认总分 72、单题老师分 2、AI 建议分 9 的分别保留。其他旧版用例全部回归通过。

上述结果是后端 API 与持久化验收，浏览器交互、实际打印成品、跨设备打包运行仍由整合验收负责。
